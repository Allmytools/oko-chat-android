# ЧА1 — перша тестова збірка OKO Android

## Для власника

- «OKO test» має остаточний бренд B4 та ідентифікатор `com.interatletika.oko.test`. Варіант F-Droid не використовує Firebase.
- Відкрий зелений `oko-build` у GitHub Actions, завантаж `oko-test-apks-debugkey` з розділу **Artifacts** і розпакуй ZIP.
- На Pixel відкрий `oko-test-arm64-v8a.apk` через «Файли» та підтвердь встановлення. За потреби дозволь встановлення для цього джерела.
- Після переходу на окремий тестовий ключ один раз перевстанови «OKO test». Перед видаленням збережи доступ до відновлення Matrix.
- Сервер Matrix поки можна вибирати. Створення акаунта в застосунку вимкнене. Вхід через обраний MAS ще треба перевірити на APK.
- Для фонових push потрібен сумісний дистриб'ютор UnifiedPush і робочий шлюз. Без них повідомлення можна побачити
  під час активної синхронізації у відкритому застосунку, а фоновий push не підтверджено. Вибір чи діагностика способу
  доставки доступні в налаштуваннях сповіщень.
- У протоколі є інструкція для робочого ключа й окремого тестового ключа. Після тесту потрібне рішення щодо домену Matrix,
  затвердження дизайну за знімками та дозвіл на публікацію.

## Збирання і статус

`-Pelement.enterprise=false` примусово обирає відкриті модулі. Підмодуль `enterprise` збірка `oko-build` не завантажує.
`-Poko.test=true` є типовим для release. Для робочої версії `-Poko.test=false` обирає `com.interatletika.oko`.
Збирання release створює APK без підпису. На push у `ai/oko-brand` workflow перевіряє режим `-Poko.test=true`
і пакет `com.interatletika.oko.test` в обох APK перед підписом. Повний комплект секретів `OKO_TEST_SIGNING_*`
дає артефакт `oko-test-apks`. Якщо всі чотири секрети відсутні, відкритий налагоджувальний ключ Element дає
`oko-test-apks-debugkey`. Частково заповнений комплект зупиняє підпис. PR запускає перевірки без секретів
і надає непідписаний артефакт `oko-test-apks-unsigned`.

SHA-256 сертифіката налагоджувального ключа Element:
`b0b051dc565c812fe17f6f3e945b4d79047123ab0da61286769eb2949197130e`.
Обидва APK перевіряються командою `apksigner verify --print-certs` і мають збігатися з відбитком вибраного ключа.

```sh
./gradlew -Pelement.enterprise=false -Poko.test=true \
  :app:assembleFdroidRelease :app:testFdroidDebugUnitTest :features:enterprise:impl-foss:testDebugUnitTest
```

Набір `:features:oko-brand-screenshots` знімає реальні Compose-компоненти привітання, бесід, повідомлень і поля вводу,
налаштувань та значок у світлій і темній темах. Для значка Layoutlib малює два ресурси APK в круглій рамці. Перший прогін записує знімки в окремому модулі, наступні можуть
порівнювати з прийнятими еталонами. Еталони Element спільного набору не змінювалися. Десять знімків фінального бренду (по п’ять на тему) доступні в артефакті `oko-brand-screenshots`.
Знімок круглої рамки отримано в Layoutlib. Тематичну маску Android і холодний запуск слід перевірити на телефоні
після встановлення підписаного APK.

Конфігурація чернетки випуску після появи підписаних APK: `v26.11.1-oko.1-test`, назва «OKO 26.11.1 · тест 1»,
`Draft` + `Pre-release`, ціль — перевірений SHA, вкладення — universal та arm64-v8a. Публікацію погоджує власник.

Локальний прогін `:features:enterprise:impl-foss:testDebugUnitTest` на фінальній палітрі дав **18 із 18**. У
[зеленому oko-build для коду `b1d10902`](https://github.com/Allmytools/oko-chat-android/actions/runs/45770363981)
пройшли тести, перевірка APK і рендер. Підпис тестових APK додано за ЧА1-02. Здача — [PR №1](https://github.com/Allmytools/oko-chat-android/pull/1).

## Зміни та контраст

Див. [OKO_PATCHES.md](../../../OKO_PATCHES.md). Заміна binding Metro делегує штатному FOSS-сервісу і тримає його часто
змінюваний файл поза правками. Джерела ресурсів у convention-плагіні дозволяють підтягувати модуль значків Element
у залежностях під час оновлень і підставляти значок OKO під час злиття ресурсів FOSS-застосунку.
Затверджений пакет — `branding/oko/paket_android/`. Gradle не генерує Kotlin з `brand.json`.
Лише погоджені токени пакета перенесено у `OkoPalette.kt`. Світла чужа бульбашка й колір посилань зберігають
значення Element.

## Оновлення для власника й інтегратора

**Встановлення.** Перший тестовий APK встанови через застосунок «Файли». Дозвіл для цього джерела Android пропонує
під час встановлення. Якщо телефон пише «Застосунок не встановлено», спочатку перевір, чи ти відкрив саме APK,
чи він підписаний, і чи підходить архітектура. Якщо є попередній «OKO test», оновлення потребує того самого ключа і
не нижчого коду версії. Для несумісного підпису обговори з інтегратором резервування та відновлення доступу перед
видаленням старої копії.

**Obtainium.** Після погодженої публікації додай джерело `https://github.com/Allmytools/oko-chat-android`. Для тестових
версій увімкни pre-release та вибери APK для своєї архітектури (для Pixel — arm64-v8a). Під час оновлень обирай той
самий канал, щоб ідентифікатор і ключ залишалися сумісними. Чернетки випусків користувачам не доступні.

**Оновлення від Element.** `oko-sync-upstream` підготовлено з вимкненим запуском. Після рішення власника потрібні
змінна `OKO_ENABLE_UPSTREAM_SYNC=true` і можливість створювати PR через GitHub Actions. Ручний запуск готує гілку,
перевіряє чисте злиття й відкриває лише чернетку PR. Тижневий тригер наведено коментарем для майбутнього погодження.
У разі конфліктів workflow записує список файлів. Для термінового оновлення без шару 2 дивись інструкцію в
`OKO_PATCHES.md`, потім перевір збірку і тести перед випуском.
