# ЧА2 — OKO test для Windows

## Встановлення

1. Відкрийте успішний запуск `oko-desktop-build` у PR №2. У розділі **Artifacts** завантажте `oko-desktop-windows-test` і розпакуйте ZIP. GitHub потребує відкритого сеансу для завантаження артефактів Actions.
2. У Провіднику скопіюйте шлях до інсталятора. У PowerShell виконайте `Get-FileHash -Algorithm SHA256 -LiteralPath '<шлях до .exe>'` і звірте значення `Hash` із `SHA256SUMS.txt` з архіву підтвердженого запуску.
3. Запустіть `Setup.exe`. Це непідписана тестова збірка, тому SmartScreen може показати невідомого видавця. На тестовому ПК після перевірки джерела й контрольної суми можна обрати «Докладніше» → «Усе одно запустити», якщо Windows пропонує цю дію.
4. На екрані входу натисніть «Редагувати» біля сервера і введіть адресу свого Matrix. `matrix.example` — заглушка. Увійдіть під наявним обліковим записом. Нові акаунти через тестовий клієнт не створюються.
5. У «Налаштування → Вигляд» вимкніть «Як у системі» та оберіть «OKO світла» або «OKO темна».
6. Якщо на тестовому ПК також установлено Element Desktop, запуск OKO може змінити обробник старих посилань `element:`. Для першої перевірки використайте окремий профіль Windows або тестовий ПК.

## Збірка і перевірка

- Джерело — [випуск Element Web/Desktop v1.12.36](https://github.com/element-hq/element-web/releases/tag/v1.12.36). Workflow перевіряє підпис вебпакета GPG, генерує `config.json` і додає ресурси OKO в тимчасовій копії. Варіант робочої версії підготовлено у `desktop/variant.json`.
- Збирач Squirrel видає тестовий інсталятор Windows x64. Портативного варіанта цей збирач не створює. Workflow перевіряє назву продукту Windows, вміст `webapp.asar`, обидві теми, відсутність адреси автооновлення й наявність файлу інсталятора.
- Playwright використовує вебпакет з інсталятора та локальну імітацію Matrix. Артефакт `oko-desktop-screenshots` містить знімки входу, домашньої сторінки й тестової кімнати (1920×1080, дві теми). Це візуальна перевірка. Дизайнерські макети для звірки — у `branding/oko/desktop/previews/`.

## Тема «Як у системі»

- `default_theme` задає світлу тему OKO, коли вибір теми за системою вимкнено. `use_system_theme` типово ввімкнено й доступне лише на рівні пристрою. Параметр у `setting_defaults` не діє. Чистий профіль із системною темою отримує вбудовану палітру Element. Доступний спосіб без правок коду — ручний вибір теми з кроку 5 вище.
- Можлива правка після погодження — у [ThemeWatcher.ts:139–152](https://github.com/element-hq/element-web/blob/v1.12.36/apps/web/src/settings/watchers/ThemeWatcher.ts#L139-L152) використовувати явно налаштовану пару тем OKO для світлої й темної системи. Зберегти високий контраст, явний вибір користувача та перехід на вбудовані теми, коли пара відсутня. 🟡, один коміт за рік до цього тегу, але зміна впливає на всі екрани й потребує регресійної перевірки. [Зміна рівнів налаштувань у Settings.tsx:960–964](https://github.com/element-hq/element-web/blob/v1.12.36/apps/web/src/settings/Settings.tsx#L960-L964) — 🔴, 56 комітів за той самий період. Такий підхід лише дозволив би типово вимкнути системний режим, без автоматичного перемикання палітр OKO.
- [protocol.ts:55–65](https://github.com/element-hq/element-web/blob/v1.12.36/apps/desktop/src/protocol.ts#L55-L65) завжди реєструє застарілу схему `element:` разом зі схемою збірки. `VARIANT_PATH` визначає `oko-test:` у метаданих пакета. Усунення дублювання під час запуску потребує погодженої зміни коду Element і перевірки SSO.

## Наступний випуск

Замінити тег у `desktop/ELEMENT_WEB_TAG`, повторити `oko-desktop-build`, перевірити знімки, встановлення та вхід. Ротація ключа Element потребує окремої звірки його відбитка. Збірка зберігає адресу автооновлення незаданою. Варіанти на майбутнє — ручне встановлення перевіреного інсталятора або окремий канал OKO з підписаними збірками.
