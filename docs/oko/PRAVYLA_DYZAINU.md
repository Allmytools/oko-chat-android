# ОКО Чат (Android) — правила дизайну для дизайн-агента (25.11.2026)

**Коротко для власника**
- Застосунок «ОКО Чат» — це копія Element X для Android з вашою назвою, значком, логотипом і кольором. Функції не змінюються.
- Дизайн-агент приймає ваші побажання і звіряє кожне з цими правилами. На кожне відповідає одним із трьох способів:
  **зелене** — робить сам, **жовте** — можна, але після погодження інтегратора, **червоне** — відмовляє й пропонує заміну.
- Межа проста: міняємо **картинки, назву й кольори**. Не міняємо **будову екранів** (розташування, кнопки, меню, шрифти).
  Саме це тримає оновлення майже автоматичними.
- Element X сам має «гнізда» для брендування: свій логотип на екрані привітання підставляється без зміни коду,
  а палітра кольорів — через одне місце.
- **Чесна примітка про колір.** Зелений ОКО (#008069) майже збігається із зеленим Element (#007A61). Тому, якщо лишити
  зелений, застосунок відрізнятиметься переважно значком, логотипом і назвою. Помітно інший вигляд дадуть лише інший колір
  акценту або кольорові основні кнопки (жовта зона).
- Затверджуєте ви за знімками **справжньої збірки** в світлій і темній темах, а не лише за малюнками агента.
- Перед стартом від вас потрібні: назва застосунку, логотип ОКО у векторі (варіант Ж) і рішення щодо кольору (розділ 11).

Підстава: код `element-hq/element-x-android` станом на 25.11.2026 (коміт `277805403f92`, після релізу v26.11.1) та історія змін
файлів за рік, з 26.11.2025 до 25.11.2026. За цей рік Element випустив 38 версій разом із виправними.

## 1. Роль дизайн-агента і порядок роботи

1. Власник описує побажання своїми словами.
2. Агент відносить побажання до зони (розділи 3–5) і відповідає за шаблоном:
   ```
   Зона: зелена / жовта / червона
   Що зроблю: …                 (для зеленої)
   Що треба погодити і чим ризикуємо: …   (для жовтої)
   Чому ні: …  Пропоную замість: …        (для червоної)
   ```
3. Якщо побажання змішане, агент ділить його на частини й відповідає по кожній.
4. Агент малює орієнтовні макети (знімки екранів Element X, перефарбовані під палітру) і збирає **пакет бренду**
   (розділ 7). Готові екрани Element X для основи макетів:
   https://element-hq.github.io/element-x-android/ (оновлюється щовівторка).
5. Пакет здається інтегратору. Інтегратор перевіряє його за розділом 8, виконавець вбудовує його в код за розділом 9, і власник
   затверджує вигляд на знімках справжньої збірки.
6. Агент не пише код застосунку і не змінює файли Element. Його результат — картинки, кольори, назва і макети.

Загальні правила проєкту ОКО діють і тут: жодних секретів (ключів, паролів) у файлах і чатах; нічого не видаляти; рішення —
за власником.

## 2. Головний принцип: ресурси й значення, а не код екранів

Оновлення Element вливаються автоматично, доки наші зміни лежать у місцях, яких Element майже не торкається. Нижче —
скільки разів за рік Element змінював кожне потрібне нам місце:

| Місце | Що там | Змін за рік | Висновок |
|---|---|---|---|
| `appicon/element/…` (значок застосунку) | шари значка | 0 | своє — окремим модулем `appicon/oko` |
| `libraries/designsystem/…/drawable/ic_notification.xml` | значок сповіщень | 0 | заміна ресурсом з тим самим ім'ям |
| `OnBoardingLogoResIdProvider.kt` (гніздо логотипа) | шукає ресурс `onboarding_logo` | 0 | логотип додається файлом, код не чіпаємо |
| `appconfig/…/ApplicationConfig.kt` | назва в текстах | 0 | 1–2 рядки |
| `appconfig/…/NotificationConfig.kt` | колір сповіщень | 0 | 1 рядок |
| `app/src/main/res/values/colors.xml` | фон заставки | 0 | не чіпати (див. 5) |
| `app/src/main/res/values/themes.xml` | заставка | 1 | жовта зона |
| `libraries/designsystem/…/theme/ColorAliases.kt` | колір бульбашок | 2 | жовта зона, 2 рядки |
| `libraries/compound/…/theme/ElementTheme.kt` | тема | 6 | **не чіпати** |
| `libraries/compound/…/tokens/generated/` | палітра Element | 7 імпортів | **не чіпати** (позначено `DO_NOT_MODIFY`) |
| `plugins/…/config/BuildTimeConfig.kt` | назва, ідентифікатор | 8 | лише значення констант |
| `features/enterprise/impl-foss/…/DefaultEnterpriseService.kt` | гніздо палітри | 11 | мінімум рядків, своє — в новому файлі |
| `features/login/…/onboarding/OnBoardingView.kt` | екран привітання | 15 | **не чіпати** |
| `app/build.gradle.kts` | збирання | 28 | 1–2 рядки |

## 3. Зелена зона — агент робить сам

| Що | Як потрапляє в застосунок | Вимоги до файлу |
|---|---|---|
| **Назва застосунку** (під значком, у системі) | `BuildTimeConfig.APPLICATION_NAME` | До ~12 символів, щоб не обрізалась під значком. Не містить «Element» |
| **Назва в текстах застосунку** («Вітаємо в …») | `ApplicationConfig.PRODUCTION_APPLICATION_NAME` | Та сама назва |
| **Значок застосунку** | новий модуль `appicon/oko` замість `appicon/element` | розділ 6.1 |
| **Значок для тематичних значків Android 13+** | шар `monochrome` того ж значка | розділ 6.1 |
| **Значок сповіщень** (у рядку стану) | ресурс `ic_notification` у теці бренду | розділ 6.2 |
| **Логотип на екрані привітання** | ресурс `onboarding_logo` (світла) + `drawable-night/onboarding_logo` (темна) | розділ 6.3 |
| **Колір акценту** (виділення, перемикачі, посилання-дії, значки, бейджі) | палітра через гніздо `semanticColorsFlow` | розділ 6.4 |
| **Колір сповіщень** (підсвітка значка в шторці) | `NotificationConfig.NOTIFICATION_ACCENT_COLOR` | = колір акценту світлої теми |

Логотип на екрані привітання — найбезпечніша зміна: Element сам шукає ресурс `onboarding_logo`. Якщо ресурс знайдено,
стандартний логотип і фонова картинка зникають без зміни коду. **Зникає і вітальний текст** («Спілкуйтесь елементарно…»), тож
усе, що має бути на цьому екрані, наприклад назва «ОКО Чат», агент малює в самому логотипі.

## 4. Жовта зона — можна, після погодження інтегратора

Кожну позицію агент описує окремо: що змінюється, на яких екранах і чим ризикуємо при оновленнях.

| Побажання | Як зробити | Ризик / ціна |
|---|---|---|
| **Основні кнопки кольором бренду** (зараз чорні у світлій і білі в темній темі) | лише палітра: `bgActionPrimaryRest/Hovered/Pressed/Disabled` | Код не міняється, але вигляд суттєво змінюється на всіх екранах. Обов'язкова перевірка контрасту тексту на кнопці |
| **Колір бульбашок повідомлень** (зараз сірі: свої й чужі) | 2 рядки в `ColorAliases.kt` (`messageFromMeBackground`, `messageFromOtherBackground`) — ці кольори не входять до палітри | Файл змінювався 2 рази за рік, тож конфлікт можливий, але дрібний. Текст і посилання мають читатися на новому фоні |
| **Значок на заставці під час запуску** (зараз заставка порожня) | `themes.xml` (`windowSplashScreenAnimatedIcon`) | Файл змінювався 1 раз за рік. Правила Android для значка заставки |
| **Кольори успіху** (зараз зелені, той самий тон, що акцент) | палітра: `*Success*` | За замовчуванням **лишаємо зеленими**: зелений тут означає «успішно», а не бренд |
| **Колір зовнішніх посилань і фокусу** (зараз сині) | палітра: `textLinkExternal`, `borderFocused` | Синій — звична ознака посилання. Міняти лише з причиною |

## 5. Червона зона — агент відмовляє і пропонує заміну

| Побажання | Чому ні | Що запропонувати |
|---|---|---|
| Інше розташування, розміри, порядок, нові чи прибрані кнопки, вкладки, меню, екрани | Це зміни в коді екранів, які Element переробляє постійно (`OnBoardingView.kt` — 15 змін за рік). Конфлікти майже в кожному оновленні | Кнопки й картки — через бота ОКО в кімнатах. Свої екрани — у панелі чату всередині ОКО |
| Свій шрифт (наприклад, Inter, як в ОКО) | Шрифт задано в згенерованих токенах і темі (`DO_NOT_MODIFY`, 7 імпортів за рік). Він змінює вимір тексту на всіх екранах | Системний шрифт телефона |
| Форма кутів, відступи, тіні, анімації | Це код компонентів, а не палітра | Лише кольори |
| Свої значки інтерфейсу (стрілки, меню, кнопки) | Набір значків Compound генерується автоматично | Лишити стандартні |
| Правка текстів інтерфейсу, крім назви | Тексти й переклади імпортуються автоматично (`localazy.xml`, `translations.xml`), правка зникне з наступним імпортом | Назву — через `ApplicationConfig`. Пояснення для менеджерів — в інструкції або повідомленні бота |
| Будь-яка правка в `libraries/compound/…/tokens/generated/`, `ElementTheme.kt`, `OnBoardingView.kt` | Файли змінюються часто або генеруються | Гнізда з розділу 3 |
| Колір фону екранів (білий / темний) | Фон заставки прив'язаний до фону теми (`colors.xml`: «Must be equal to …ThemeBg»), до нього ж — контраст усієї палітри | Колір бренду — в акценті й кнопках |
| Назва чи логотип Element або схожі на них у нашому бренді | Торговельна марка Element (розділ 10) | Лише власна символіка ОКО |
| Версія для iPhone | Окремий застосунок, окрема робота й витрати | Окреме рішення власника |
| Зміна функцій (прибрати дзвінки, додати кнопку тендера) | Це не дизайн | Окреме завдання виконавцю через інтегратора |

Окремо: на екрані входу через Element Classic лишаються логотипи Element. Це опис справжнього застосунку Element, і наші
менеджери цього екрана не побачать, тож не чіпаємо.

## 6. Технічні вимоги до файлів

### 6.1. Значок застосунку (адаптивний)
- Три шари по **108×108 dp**: `foreground` (логотип), `background` (суцільний фон без прозорості), `monochrome`
  (одноколірний силует для тематичних значків Android 13+).
- Усе важливе — у **центральному колі діаметром 66 dp**. Решту може обрізати форма значка конкретного телефона.
- Формат: вектор (SVG, який конвертується у VectorDrawable) або растр у розмірах за щільністю:
  `foreground`/`monochrome` — 108 / 162 / 216 / 324 / 432 px (mdpi…xxxhdpi).
- Застосунок підтримує Android 7+, тому потрібні й **звичайні значки** `ic_launcher` та `ic_launcher_round`:
  48 / 72 / 96 / 144 / 192 px.
- Окремий значок 512×512 px для каталогу F-Droid.
- Перевірка: коло, квадрат із заокругленням, «краплина», тематичний значок на світлих і темних шпалерах.

### 6.2. Значок сповіщень
- Одноколірний силует на прозорому фоні: Android малює лише форму (прозорість), колір ігнорує.
- Вектор, 24×24 dp (у Element 32 dp з полем), без дрібних деталей і тексту. Має впізнаватися з розміру ~16 px.

### 6.3. Логотип на екрані привітання
- Ім'я ресурсу — рівно `onboarding_logo`. Дві версії: для світлої (`drawable/`) і темної (`drawable-night/`) теми.
- Показується по центру, у власному розмірі, з полями 16 dp. Тому вектор задає розмір явно (орієнтир ~200×200 dp),
  а растр подається в xxhdpi (~600×600 px).
- Містить усе, що має бути на екрані привітання (знак + назва), бо вітальний текст Element зникає.

### 6.4. Палітра
- **Два набори значень:** світла і темна тема. Чорна тема (AMOLED) береться з темної автоматично.
- Міняємо **лише токени акценту** (і, за погодженням, токени основних кнопок). Значення Element для довідки:

| Токен | Світла (Element) | Темна (Element) | Де видно |
|---|---|---|---|
| `bgAccentRest` | #007A61 | #129A78 | заливка акцентних елементів, перемикачі |
| `bgAccentHovered` | #006B52 | #17AC84 | натискання / наведення |
| `bgAccentPressed` | #005C45 | #1FC090 | натиснутий стан |
| `bgAccentSelected` | зелений з прозорістю | зелений з прозорістю | вибране |
| `bgAccentSubtle` | #F1FBF6 | #001F0E | легка підкладка |
| `bgBadgeAccent` / `textBadgeAccent` | #C6EEDB / #005C45 | #002E1B / #1FC090 | бейджі |
| `borderAccentPrimary` / `borderAccentSubtle` | #007A61 / #0BC491 | #129A78 / #005A43 | рамки |
| `gradientActionStop1…4` | #98E1C1 → #005C45 | #1FC090 → #003D29 | градієнтні кнопки |
| `iconAccentPrimary` / `iconAccentTertiary` | #007A61 / #009B78 | #129A78 / #007A62 | значки |
| `textActionAccent` | #007A61 | #129A78 | текстові дії |
| *(жовта)* `bgActionPrimaryRest/Hovered/Pressed/Disabled` | #1B1D22 / #3C4045 / #4C5158 / #A6ADB7 | #EBEEF2 / #BDC3CC / #A3AAB4 / #4A4F55 | основні кнопки |

- **Контраст (обов'язково, таблицею в пакеті):**
  - `textActionAccent` на фоні екрана (`#FFFFFF` / `#101317`) — не менше **4,5 : 1**;
  - текст на кнопці (`textOnSolidPrimary`: білий у світлій, `#101317` у темній) на `bgAccentRest` і, якщо міняємо,
    на `bgActionPrimaryRest` — не менше **4,5 : 1**;
  - значки й рамки (`iconAccentPrimary`, `borderAccentPrimary`) на фоні — не менше **3 : 1**;
  - стани Rest → Hovered → Pressed відрізняються на око.
- Агент не задає жодного кольору поза цим переліком.

## 7. Пакет бренду — що здає агент

Пакет лежить у репозиторії застосунку `Allmytools/oko-chat-android`, тека `branding/oko/` (форк створено 26.11.2026).

```
branding/oko/
  brand.json                 назва, кольори (див. нижче)
  icon/foreground.svg        108×108, логотип у колі 66 dp
  icon/background.svg        або колір у brand.json
  icon/monochrome.svg
  icon/legacy_*.png          48…192 px (звичайний і круглий)
  icon/store_512.png
  notification/ic_notification.svg
  onboarding/onboarding_logo_light.svg   (або .png xxhdpi)
  onboarding/onboarding_logo_dark.svg
  previews/                  макети: привітання, список чатів, чат, налаштування, сповіщення — світла й темна
  PEREVIRKA.md               таблиця контрасту, перелік зон і погоджень
```

`brand.json`:
```json
{
  "app_name": "ОКО Чат",
  "notification_accent": "#RRGGBB",
  "light": { "bgAccentRest": "#RRGGBB", "...": "лише токени з розділу 6.4" },
  "dark":  { "bgAccentRest": "#RRGGBB", "...": "..." },
  "yellow_zone_approved": ["перелік погоджених позицій з розділу 4, з датою"]
}
```
Ідентифікатор застосунку (`applicationId`) — не справа дизайнера. Його один раз визначає інтегратор із власником, і
після першого випуску він не змінюється.

## 8. Перевірка пакета (інтегратор)

1. У пакеті немає нічого з червоної зони. Жовті позиції мають погодження з датою.
2. Розміри й шари значків відповідають розділу 6. Логотип не виходить за коло 66 dp.
3. Таблиця контрасту повна, усі значення в межах норм.
4. У жодному файлі немає назви чи логотипа Element.
5. Після вбудовування — знімки **справжньої збірки** (APK на тестовому телефоні або окремий набір знімків з нашою палітрою)
   у світлій і темній темах:
   - привітання;
   - вхід;
   - список чатів;
   - чат з повідомленнями;
   - налаштування;
   - сповіщення в шторці;
   - значок на робочому столі звичайний і тематичний.

   Власник затверджує саме ці знімки.

## 9. Як пакет лягає в код (для виконавця)

- **Свій код — у нових файлах і модулях, у чужих файлах — мінімум рядків:**
  - модуль `appicon/oko` (за зразком `appicon/element`) і заміна залежності в `app/build.gradle.kts` (1 рядок);
  - тека ресурсів бренду, підключена до модуля `app`, з `ic_notification` та `onboarding_logo`. Ресурси модуля `app` мають
    перевагу над ресурсами бібліотек з тим самим ім'ям, тож файли Element лишаються незмінними;
  - палітра: новий файл з `SemanticColors.copy(…)` лише для токенів з `brand.json` (світла й темна), а в
    `DefaultEnterpriseService.semanticColorsFlow` — один рядок, що повертає нашу палітру. Альтернативу — заміну через DI
    власною реалізацією `EnterpriseService` — виконавець оцінює окремо;
  - назва й колір сповіщень — значення констант у `BuildTimeConfig`, `ApplicationConfig`, `NotificationConfig`.
- Палітра підставляється під час роботи застосунку, а стандартні знімки-тести Element рендерять палітру за замовчуванням.

  окремий набір знімків бренду.
- Якщо після імпорту нових токенів Element зник або перейменувався токен з `brand.json`, збирання впаде з помилкою. Це
