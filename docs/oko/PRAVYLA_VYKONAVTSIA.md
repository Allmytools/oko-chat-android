# OKO (Android) — правила для виконавців

Діють для кожного завдання в цьому репозиторії. При розбіжності з `AGENTS.md` (правила Element) діють ці правила.

## Ролі
- **Власник** — Руденко Олександр. Ухвалює рішення, дає слово на злиття в `oko/main` і на публікацію випусків.
- **Інтегратор** — Claude. Пише завдання (`docs/oko/zavdannia/`), перевіряє роботу, видає уточнення в протоколі.
- **Виконавець** — Codex (та інші ШІ-виконавці). Програмує за завданням у гілках `ai/*`.

## Головний принцип
Застосунок «OKO» — копія Element X з нашою назвою, значком, логотипом і кольорами. Функції не змінюємо. Нові версії
Element мають вливатися майже автоматично, тому кожна наша зміна мінімальна і в місцях, яких Element майже не торкається.

## Зони — оцінюєш сам перед кожною зміною
Перед будь-якою зміною у файлі Element перевір його історію за рік (`git log` в `upstream`).
- 🟢 **Зелена** — робиш: ресурси й значення, яких Element майже не чіпає (0–3 зміни файлу за рік). Свій код — у нових
  файлах і модулях.
- 🟡 **Жовта** — лише з погодженням (власника через інтегратора): правки до ~20 рядків у файлах, які Element змінює рідко
  (до ~5 разів за рік), або зміни, що помітно міняють вигляд усіх екранів. Пиши в протокол: що, який файл, скільки змін за
  рік, чим ризикуємо — і чекай рішення.
- 🔴 **Червона** — не робиш: зміни поведінки й будови екранів; файли, які Element змінює часто (понад ~10 разів за рік);
  згенеровані файли (`tokens/generated`, `DO_NOT_MODIFY`); `ElementTheme.kt`; тексти й переклади (`localazy.xml`,
  `translations.xml`); шрифти; назва й логотип Element у нашому бренді.

Сумніваєшся — вважай зону вищою. Якщо завдання чи побажання потрапляє в жовту або червону зону — не роби мовчки:
попередь у протоколі, поясни ціну при кожному оновленні й запропонуй безпечнішу заміну.

Кожну зміну записуй у `OKO_PATCHES.md` (корінь): файл, рядки, навіщо, зона, як перевірити. У файлах Element — коментар
`// OKO:` біля кожної нашої правки. Заголовки ліцензій і `LICENSE` не чіпати.

## Гілки й здача
- Робота — у гілці `ai/<назва>` від `oko/main`. Результат — PR у `oko/main`. **Не зливати**: зливає інтегратор після
  слова власника.
- Коміт і push після кожного етапу, але не рідше ніж раз на 30 хвилин. Не зупиняйся посеред етапу.
- **Самоперевірка кожні 30 хвилин:** чи був проміжний коміт з push? чи не повторюю я ті самі запуски чи пояснення? чи
  рухаюсь до здачі? Якщо ні — коміт «НЕЗАВЕРШЕНО: …» з причиною і тим, що лишилось, і зупинка.
- Розкладів і автоматичних перевірок за таймером не створюй. Між кроками роботи сам переглядай протокол.
- **Здача** — коміт «ПЕРЕВІР: <код завдання>», лише із зеленим прогоном збирання й тестів на фінальному коміті. Якщо
  ти не бачиш результатів GitHub Actions — так і напиши в протоколі, інтегратор перевірить.
- Після здачі зупиняєшся й чекаєш нового повідомлення. Запис «ВІДБІЙ» у протоколі — зупинитися негайно.

## Безпека
- Ключ підпису, паролі, токени — **лише в секретах GitHub**. Ніколи в чат, протокол, код, журнали чи звіти.
- Нічого не видаляти (гілки, файли, workflow): вимикати — умовою або переліком для власника.
- Платні сервіси — лише з рішення власника.
- Runner-и сервера ОКО (`oko-probe`, `ai/oko-server`) не використовувати — лише хмарні Linux runner-и GitHub.
- Нічого не публікувати (Release, репозиторій оновлень) без слова власника — лише чернетки.

## Протокол
`docs/oko/PROTOKOL.md`: розділ на кожне завдання. Записи — з датою й часом за Києвом. Виконавець пише туди питання,
блокери й здачу; інтегратор — уточнення й рішення.
