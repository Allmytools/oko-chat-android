# ОКО — завдання ЧА1: збірка застосунку «OKO» (брендована копія Element X Android), перша тестова версія (26.11.2026)

**Виконавець:** Codex, «ОКО · Чат Android». Мітка на початку кожної відповіді: «[ОКО · Чат Android]».
**Інтегратор:** Claude (перевіряє роботу, видає уточнення). Злиття в `oko/main` і публікація — лише зі слова власника.
**Репозиторій:** `Allmytools/oko-chat-android` (цей). **Протокол:** `docs/oko/PROTOKOL.md`, розділ «ЧА1».
**Загальні правила роботи:** `docs/oko/PRAVYLA_VYKONAVTSIA.md` — прочитай першими.

## Мета
Зібрати застосунок **«OKO»** для Android. Це копія Element X з нашою назвою, значком, логотипом і кольорами, функції
**не змінюються**. Результат — підписаний APK, який власник встановлює на свій телефон, і налагоджений процес, за яким
наступні версії Element вливаються майже автоматично.

## Прочитай першим
1. **Правила дизайну:** `docs/oko/PRAVYLA_DYZAINU.md`. Розділ 9 — як пакет лягає в код, розділ 2 — які файли Element
   змінює часто.
2. **Пакет бренду дизайнера:** інтегратор покладе його в `branding/oko/` цього репозиторію (структура — розділ 7 правил:
   `brand.json`, значки, `ic_notification`, `onboarding_logo`, `oko_splash`, `PEREVIRKA.md`) і напише про це в протокол.
3. **`AGENTS.md` у корені — правила Element для їхніх розробників.** Код пиши за їхнім стилем (Timber, Compound, Metro,
   ktlint), але правила їхніх PR (мітки `pr-`, Localazy, `temporary.xml`, ліміти PR) до нас **не застосовуються**. Файл
   `AGENTS.md` не змінюй. При розбіжності діють документи `docs/oko/`.

Якщо пакета ще немає — каркас Е1 роби на тимчасових зображеннях з позначкою `TEMP` (простий знак «OKO» на зеленому
`#008069`), а в протокол запиши, чого чекаєш.

## Що входить (погоджено інтегратором 25.11)
**Шар 1 — бренд (зелена зона):**
- назва `OKO`: `BuildTimeConfig.APPLICATION_NAME` і `ApplicationConfig.PRODUCTION_APPLICATION_NAME`.
  `DESKTOP_APPLICATION_NAME` лишається `"Element"`, бо менеджери на комп'ютері користуватимуться Element Web/Desktop;
- значок застосунку: новий модуль `appicon/oko` за зразком `appicon/element` (адаптивний, monochrome, legacy) і заміна
  залежності в `app/build.gradle.kts`;
- `ic_notification` і `onboarding_logo` (світла й темна) — в окремій теці ресурсів бренду, підключеній до модуля `app`.
  Ресурси `app` перекривають однойменні ресурси бібліотек, тому файли Element **не змінюються**;
- палітра акценту з `brand.json`: новий файл з `SemanticColors.copy(…)` лише для токенів з `brand.json` (світла й темна).
  У `DefaultEnterpriseService.semanticColorsFlow` — мінімальна правка, що повертає нашу палітру. Альтернативу — заміну
  через DI власною реалізацією — оціни і вибери ту, що дає менше конфліктів; обґрунтуй у звіті;
- `NotificationConfig.NOTIFICATION_ACCENT_COLOR` — акцент світлої теми;
- `OnBoardingConfig.CAN_CREATE_ACCOUNT = false`: реєстрацію акаунтів у застосунку вимкнено.

**Шар 2 — погоджені жовті позиції (лише ці):**
- основні кнопки кольором бренду: токени `bgActionPrimary*` через ту саму палітру (`#008069` / `#21C063`, остаточні
  значення — з `brand.json`);
- колір бульбашок: 2 рядки в `libraries/designsystem/…/theme/ColorAliases.kt` (`messageFromMeBackground`,
  `messageFromOtherBackground`), значення з `brand.json`.
- знак OKO на заставці під час запуску (погоджено 25.11): у `app/src/main/res/values/themes.xml` і
  `values-night/themes.xml` по одному рядку — `windowSplashScreenAnimatedIcon` з `@drawable/transparent` на
  `@drawable/oko_splash` (файли `oko_splash` — у пакеті бренду, світла й темна).

**Не входить:** мікрофон зеленим колом, галочки прочитання, кнопка «переслати», логотип у верхній панелі, пігулки груп,
шпалери, шрифт, будь-які зміни поведінки. Якщо побачиш у пакеті щось поза цим переліком — не роби, запиши в протокол.

## Етапи

### Е0. Репозиторій — зроблено інтегратором 26.11
- `Allmytools/oko-chat-android` — відкрита копія `element-hq/element-x-android`. Основа — гілка **`oko/main`** = тег
  Element **`v26.11.1`** (коміт `3a61e4fd`) + документи `docs/oko/`.
- Твоя робоча гілка: **`ai/oko-brand`** від `oko/main`. Результат — PR у `oko/main`, **не зливати**.
- Додай `upstream` → `element-hq/element-x-android` (потрібен для Е4).
- Підмодуль `enterprise` (приватний, Element) не підтягувати. Збирання FOSS — перевір у `settings.gradle.kts` і
  `docs/`, як вимикається enterprise-збірка, і опиши в звіті.
- **Actions у копіях репозиторіїв GitHub вимкнено за замовчуванням.** Якщо твої workflow не запускаються — напиши
  в протокол «увімкнути Actions», це робить власник. Перевір, які workflow Element запустяться в нашій копії (розклади,
  синхронізації Localazy, тріаж, Sonar тощо), і вимкни ті, що потребують чужих секретів або сервісів: умовою
  `if: github.repository == 'Allmytools/oko-chat-android'` у нашому наборі або переліком для власника, що вимкнути в UI.
  Файли не видаляй.

### Е1. Бренд
- Усе зі «Що входить».
- **Реєстр наших змін** `OKO_PATCHES.md` у корені: кожна зміна окремим пунктом — файл, що змінено (рядки), навіщо, як
  перевірити. Це головний документ для майбутніх оновлень: за ним агент повторює зміну, якщо Element переробить файл.
- Свій код — у нових файлах і модулях; у файлах Element — мінімум рядків, кожен з коментарем `// OKO:`.
- Заголовки ліцензій і `LICENSE` не чіпати.

### Е2. Ідентифікатор, підпис, сповіщення
- `applicationId`: `com.interatletika.oko`. Для тестових збірок — суфікс `.test`, назва «OKO test», щоб тестова й робоча
  версії могли стояти поруч. **Після першого робочого випуску ідентифікатор не змінюється.**
- Варіант збирання: **`fdroid`** (без Google і Firebase). Варіант `gplay` зі зміненим ідентифікатором не отримуватиме
  сповіщень через Firebase Element. Сповіщення — UnifiedPush (власний ntfy налаштуємо окремо). У звіті чесно опиши, як
  поводяться сповіщення в тестовій збірці без ntfy і що бачить користувач.
- **Підпис.** Робочий ключ створює власник або IT-адміністратор і кладе в секрети репозиторію
  (`OKO_SIGNING_STORE_BASE64`, `OKO_SIGNING_STORE_PASSWORD`, `OKO_SIGNING_KEY_ALIAS`, `OKO_SIGNING_KEY_PASSWORD`).
  У чат, протокол, код і журнали ключ і паролі **не потрапляють**. Поки секретів немає — тестова збірка `.test`, підписана
  окремим тестовим ключем, теж через секрети. Напиши в протокол інструкцію, як створити ключ (`keytool`, тип, термін ≥
  25 років) і зберегти резервну копію.
- Сервер Matrix у тестовій збірці **не прив'язувати** (вибір сервера лишається), бо домен ще не підтверджено. Підготуй
  прив'язку (`accountProviderAllowList` / `canConnectToAnyAccountProvider`) як вимкнену константу з одним місцем для
  домену і опиши, як увімкнути.

### Е3. Збирання і перевірка (GitHub Actions форка)
- Окремий workflow `oko-build`: збирання `fdroid` release APK (universal і arm64), підпис із секретів, модульні тести
  змінених модулів, артефакт APK. Існуючі workflow Element, які потребують їхніх секретів чи сервісів, вимкнути **в
  нашому workflow-наборі**, не видаляючи файли.
- **Не використовувати runner-и сервера ОКО** (`oko-probe`, `ai/oko-server`): збирання Android важке. Лише хмарні Linux
  runner-и GitHub.
- **Знімки бренду:** окремий набір знімків-тестів у нашому модулі (Paparazzi) з нашою палітрою, світла й темна:
  привітання, список бесід, чат з повідомленнями (свої й чужі бульбашки), поле вводу, налаштування, значок. Спільні знімки
  Element не перезаписувати. У звіті — контраст часу на темній зеленій бульбашці (вимога: ≥ 4,5:1).
- Випуск: GitHub Release з позначкою **pre-release**, тег `v26.11.1-oko.1-test`, APK у вкладеннях. Публікація —
  **лише зі слова власника**: підготуй чернетку випуску.

### Е4. Процес оновлень (лише підготувати, не вмикати)
- Workflow `oko-sync-upstream` (вручну і раз на тиждень): знаходить новий тег Element; гілка `ai/oko-sync-<тег>`, злиття
  тегу в нашу версію, збирання, тести, знімки бренду; PR у `oko/main` з переліком конфліктів. **Автоматично нічого не
  публікує.**
- Правило безпеки: якщо шар 2 не зливається, а в новому Element є виправлення безпеки — збирається версія лише з шаром 1.
  Опиши, як це зробити (позначки шарів у `OKO_PATCHES.md`).
- Інструкція для власника (простою мовою, до 1 сторінки): встановлення APK на телефон; налаштування Obtainium на сторінку
  випусків, щоб оновлення приходили самі; що робити, якщо телефон пише «застосунок не встановлено».
